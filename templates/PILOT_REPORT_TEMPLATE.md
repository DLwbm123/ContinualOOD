# Pilot 报告

状态：`NOT_RUN / PARTIAL / REAL_RUN_COMPLETED`（由实际运行填充）

## 1. 版本与可复现性

记录 source lock、配置、checkpoint、数据版本、划分与流顺序哈希，以及实际命令和运行时间。明确真实医学数据、合成单元测试和 mock 的边界。

## 2. 数据与评价范围

填写实际患者/检查/中心数、dev/stream/probe 人数、几何异常、重复数据、排除项及其原因。说明全视野还是裁剪输入，完整标注还是部分标注。缺失字段填写“未确认”，不填 0。

## 3. 基线正确性

模型加载与冻结检查、native parity、候选插桩覆盖、空间往返检查。未通过的项目不得标成“复现完成”。

## 4. 主要结果

从真实运行产物自动汇总 B0、B1、C0、C1、B2、B3、B4；不得手工填造数值。报告固定阈值结果、FROC 工作点和支持这些指标的标注范围。没有运行的行标记 NOT_RUN。

## 5. 机制诊断

分别回答：候选是否已经覆盖真病灶？当前参考是否有帮助？历史比 C1 是否有额外价值？匹配与写入保护分别改变了什么？不存在兼容参考时是否正确回退？

## 6. 持续性与负迁移

旧域返回、固定 probe 矩阵、不同顺序、状态重置、记忆写入/检索覆盖与失效病例。报告正结果与负结果。

## 7. 资源

端到端时延、缓存后模块时延、额外 forward 数、显存/RAM 峰值、真实记忆字节数、缓存和磁盘用量。

## 8. 安全性与信息隔离测试

填写 T01–T22 的 PASS / FAIL / NOT_APPLICABLE / NOT_RUN。每项给出日志或测试产物路径，不能把 NOT_RUN 写成 PASS。

## 9. 限制和下一步

将结论限定在已完成样本、任务和信息条件内。明确是否值得扩大 S1、扩展 S2/S3，或应转向候选生成。没有提升时说明，不通过改评价规则美化。
